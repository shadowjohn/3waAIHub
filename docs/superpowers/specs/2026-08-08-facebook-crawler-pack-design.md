# Facebook Crawler HubPack Design

Date: 2026-08-08

Status: approved design; pending written-spec review

## Goal

Add an installable `facebook-crawler` HubPack for manually started,
asynchronous collection of recent posts from authorized Facebook pages and
groups. One run accepts multiple targets and returns an Apify-like dataset
that clients can inspect after the request has finished.

The first deployment may be 3wa, but the Pack is portable. Any 3waAIHub host,
including a future NCHC host, can install and operate its own copy.

Typical sources are public official pages and news or public-information
groups, such as government agency pages. A private group is eligible only
when the selected Facebook account has already joined it manually.

## Selected Approach

Adapt the supplied Python Playwright crawler into a governed Hub Pack runner.
Keep 3waAIHub responsible for authentication, ownership, task lifecycle,
artifacts, retention, and API documentation. Keep browser extraction inside
the Pack.

Each installed node owns its browser profiles and runs locally submitted
crawl tasks. A profile is node-pinned: its browser state is never copied to
another Hub or Cluster station.

Alternatives considered:

- Wrapping the supplied standalone web server would duplicate Hub auth,
  storage, retention, and task state, so it is not used.
- Replicating browser cookies through the Cluster Router would enlarge the
  credential boundary and make session failures difficult to diagnose, so it
  is deferred.
- Requiring interactive login for every run would avoid stored browser state
  but make background work impractical, so reusable owner-scoped profiles are
  used.

## Phase A Scope

The first release provides:

- installation on Linux Docker and Windows WSL2 Linux Docker;
- owner-scoped Facebook browser profiles on each installed node;
- password-assisted or interactive browser profile setup;
- manual asynchronous runs with 1 to 30 page or group targets;
- 10 to 30 recent posts per target, default 10;
- per-target partial results and stable error codes;
- JSONL artifact download plus paged dataset JSON;
- latest-run lookup for the authenticated API member;
- API documentation, test-center examples, and an offline fixture smoke.

Phase A does not install a scheduler or crontab. `nchc_ai` may schedule calls
to the manual run API externally.

## Installation And Node Ownership

The Pack ID is `facebook-crawler`; its public crawl mode is
`facebook_crawl`. It uses a CPU Playwright container and the existing shared
task queue, cancellation, logs, artifacts, and retention machinery. It does
not request a GPU lease.

Installing the Pack on multiple hosts creates independent service instances.
Profile IDs are valid only on the host that created them. Phase A profile
management and crawl submission use that host's local `api.php`; the Cluster
Router does not relay these modes yet. This keeps multi-host installation
useful without copying Facebook sessions between stations.

The runner uses the existing `public_egress` network boundary. Submitted
targets must be HTTPS Facebook URLs. Navigation is restricted to Facebook
hosts needed by the login and feed flow; links found inside posts are
recorded but never followed.

## Profile Lifecycle

Profile metadata is stored in one new Hub table,
`facebook_crawler_profiles`. It contains an opaque ID, `owner_member_id`,
local node identity, display name, state, last verification time, and
timestamps. It never contains a Facebook password, cookie, browser storage
state, or proxy secret.

Browser storage state lives below the private Hub data root, outside all Web
roots. Linux directories use `0700` and files use `0600`; Windows installation
applies an equivalent service-account-only ACL. The file path is generated by
Hub and is never accepted from a client or returned by an API.

Profiles have these states:

```text
preparing -> ready -> reauth_required -> ready
                      \-> deleted
```

`POST api.php?mode=facebook_profile_start` accepts a profile name and one of
two setup methods:

1. `browser`: start a short-lived interactive Chromium login session.
2. `password`: pass username and password directly to the local login broker;
   if Facebook requires 2FA, checkpoint confirmation, or CAPTCHA, continue in
   the same short-lived browser session.

The password exists only in the HTTPS request and login broker memory. It is
not serialized into a task, database row, command line, environment file,
artifact, or log. Password-assisted setup is rejected when Hub is not served
over HTTPS.

The login URL is one-time, owner-bound, and expires after 10 minutes. The
interactive view uses a bundled noVNC client through an authenticated Hub
relay; the login broker and browser ports are not exposed directly. The
one-time proof is carried in the URL fragment, exchanged in a POST body, and
then removed, so it cannot enter normal request-URI access logs. Its browser
container can navigate only within the Facebook login flow. All noVNC assets
are bundled with the Pack; no CDN is required. Detecting a valid Facebook
login cookie completes profile setup and closes the interactive session.

Supporting profile operations are:

- `GET api.php?mode=facebook_profile_status&profile_id=...`
- `POST api.php?mode=facebook_profile_reauth`
- `POST api.php?mode=facebook_profile_delete`

All profile operations require `facebook_crawl` mode permission. Any valid
Token belonging to the same API member and carrying that permission may use
that member's profile. Other members receive a not-found response.
Administrators may revoke or delete a profile but cannot view or download its
browser state.

## Crawl Contract

`POST api.php?mode=facebook_crawl` accepts JSON:

```json
{
  "profile_id": "fbp_example",
  "targets": [
    {"url": "https://www.facebook.com/example.page"},
    {"url": "https://www.facebook.com/groups/123456789"}
  ],
  "limit_per_target": 10
}
```

`profile_id` is optional for public targets. Supplying it enables the saved
Facebook session and is required for a private group. `targets` contains 1 to
30 unique page or group URLs. `limit_per_target` is 10 to 30 and defaults to
10. Clients cannot set scroll count, browser flags, user agent, fingerprint,
proxy, executable, command, host path, or output path.

Hub validates ownership and target URLs before creating the task, then stores
only the opaque profile ID and normalized crawl options. The worker resolves
the private browser state after it starts. The password and raw browser state
can therefore never enter task metadata.

Only one task may use a profile at a time. Additional tasks remain queued with
`waiting_profile` rather than opening concurrent Facebook sessions. Anonymous
public runs use the Pack's normal CPU concurrency limit.

The submit response uses the existing async contract:

```text
task_id, status_url, result_url, log_url, cancel_url,
artifact_url_template
```

## Extraction And Dataset

The supplied crawler's existing page/group discovery, health checks, bounded
scrolling, retry classification, post URL normalization, content cleanup,
and JSONL writer are reused. Phase A excludes hashtag search because its
result layout is less stable than page and group feeds.

Each dataset item preserves the source crawler's stable fields:

```text
source_url, post_url, index, content, links, extraction,
posted_at, fetched_at, discovery_mode, discovery_query
```

The runner normalizes URLs and deduplicates records within a run by canonical
post URL, falling back to source URL plus normalized-content SHA-256. It does
not maintain a second long-lived post database in Hub.

A successful task publishes two standard artifacts:

- `facebook_posts_jsonl`: the complete run dataset;
- `facebook_crawl_report`: run settings, per-target outcome, counts, elapsed
  time, Pack/browser version, and bounded non-secret warnings.

Existing `tasks` are the run records and existing artifacts are the dataset
store. No duplicate run, target, or post tables are added.

Two read APIs provide the Apify-like convenience layer:

- `GET api.php?mode=facebook_run_last` returns the member's latest completed
  `facebook_crawl` task and its result/dataset links.
- `GET api.php?mode=facebook_dataset_items&task_id=...&offset=0&limit=100`
  returns owned JSONL items as JSON. Omitting `task_id` selects the latest
  completed run. `limit` is capped at 500.

Task and dataset lookup is member-scoped and still requires a Token with
`facebook_crawl` permission. The JSONL artifact follows the existing 30-day
artifact retention, pin, acknowledgment, and purge behavior. A purged dataset
returns `410 dataset_expired`. Users may pin, acknowledge, or purge artifacts
through the existing task retention controls.

## Outcomes And Errors

Every target records one of:

```text
completed, empty, not_accessible, login_required,
navigation_failed, extraction_failed
```

An inaccessible private group is recorded as `not_accessible` and skipped;
it does not fail other targets. A run succeeds with outcome `complete` when
all targets complete or are empty, and `partial` when at least one target
produces a valid result while another is skipped or fails. If no target can
be processed, the task fails with `no_accessible_targets`.

Login walls, expired sessions, checkpoints, and session failures are never
automatically retried. They mark the profile `reauth_required` and fail the
task with `profile_reauth_required`. Transient navigation failures may retry
at most twice per target with bounded backoff. Cancellation stops the browser,
publishes no partial dataset as a successful result, and releases the profile
lock.

Logs and reports redact credentials, cookies, storage-state paths, request
bodies, authorization headers, and browser session URLs.

## Safety Boundaries

The Pack collects only content visible to the selected account. It does not:

- create or join Facebook accounts or groups;
- bypass CAPTCHA, checkpoint, 2FA, login walls, or access controls;
- use OCR or vision services to solve CAPTCHA;
- deep-scroll historical feeds or promise complete historical coverage;
- expose arbitrary Playwright flags, scripts, headers, proxies, or paths;
- guarantee uninterrupted collection or an alerting SLA.

The operator remains responsible for source authorization, Facebook terms,
and applicable law. Phase A defaults are intentionally shallow to reduce
account and source load.

## Administration And Documentation

Marketplace and service-management pages use the existing Pack presentation.
The description explains in Chinese that the Pack performs lightweight,
recent-post collection from authorized Facebook pages and groups, uses CPU,
and may require manual re-login.

The test center provides:

- profile readiness and reauthentication status;
- a manual multi-target submit form;
- task/result links and a dataset preview;
- the generic API examples for submit, polling, result, artifact, latest run,
  and paged dataset retrieval.

New UI strings use the existing `__()` i18n path. No external JavaScript,
CSS, font, or icon asset is loaded at runtime.

## Validation

The smallest acceptance set is:

1. manifest validation proves CPU async routing and Linux/Windows WSL target
   support;
2. URL and contract tests reject non-Facebook URLs, duplicates, more than 30
   targets, and limits outside 10 to 30;
3. ownership tests prove one member cannot inspect, use, reauthenticate,
   delete, or read datasets from another member's profile or task;
4. secret-handling tests prove passwords and browser state never appear in
   task input, database metadata, command arguments, logs, or API responses;
5. supplied local fixtures produce valid page/group JSONL and report
   artifacts, including partial `not_accessible` behavior;
6. task lifecycle tests prove profile serialization, cancellation cleanup,
   retention, latest-run lookup, JSONL pagination, and expired-dataset errors;
7. a real smoke logs in manually, collects 10 recent posts from an approved
   official public target, downloads the artifact, and leaves no browser
   process after completion;
8. Windows WSL smoke verifies the same Pack runner and private profile mount;
9. new public PHP files use `0755`, JavaScript/CSS use `0644`, and public
   directories use `0755`.

## Phase B TODO

Phase B may add these only after real Phase A usage:

- recurring Hub schedules and monitoring; until then `nchc_ai` schedules the
  manual API;
- Cluster Router profile registration and node-pinned dispatch without
  copying browser state;
- hashtag discovery;
- measured per-profile concurrency controls beyond the Phase A single lock;
- richer media metadata or comment collection when a concrete consumer needs
  it.

Threads.net is not part of this Facebook Pack. It requires a separate source
contract if requested later.
