# Cluster 子節點名稱與連線燈號

## 目標

統一入口應在子節點變更站台名稱後自動更新顯示名稱，並在總覽頁清楚標示每台子節點是否可用。

## 範圍

- 子節點的已驗證 `cluster_status.php` 回應加入目前的站台名稱。
- 統一入口每次成功取得子節點的 manifest 與 status 後，以回傳名稱更新 `cluster_stations.display_name`。
- 總覽頁的每個站台頁籤顯示可及性燈號與文字：綠燈「可連線」、紅燈「無法連線」。
- Cluster 管理頁沿用相同狀態，避免總覽與管理頁判定不同。

## 狀態判定

統一入口既有 cron 每分鐘主動刷新子節點；子節點不是固定推送資料。

- 綠燈：最近一次刷新沒有 `last_error`，且 manifest 與 status 快照均在 150 秒內。
- 紅燈：最近一次刷新發生連線、逾時、驗證或資料格式錯誤；或沒有明確錯誤但快照已超過 150 秒。
- 150 秒容許一次漏跑與 30 秒排程／多站依序請求抖動，避免把正常的一分鐘刷新誤判為失聯。

第一版不顯示黃燈。未來若需要，黃燈保留給版本、Pack 或相容性待更新，且不與連線失敗混用。

## 資料流

1. 子節點收到既有 `cluster_status.php` 的授權請求，回傳 `display_name` 與既有健康快照。
2. 統一入口的既有刷新流程驗證 manifest 和 status；成功後將 `display_name` 與快照一併保存。
3. Dashboard 與 Cluster 管理頁從同一筆 station 資料推導綠／紅燈，不新增資料表或前端輪詢。
4. 刷新失敗時保留最後已知名稱與快照，只記錄既有安全的錯誤代碼，狀態改為紅燈。

## 測試

- 成功刷新會更新既有子節點名稱。
- 刷新失敗不覆寫既有名稱。
- 150 秒內且無錯誤的站台為綠燈。
- `last_error` 或超過 150 秒的快照為紅燈。
- Dashboard 頁籤和 Cluster 管理頁都使用相同狀態與文字。

## 非目標

- 不新增背景排程、資料表、前端輪詢或黃色燈號。
- 不把內部錯誤內容或站台 Token 顯示在 UI 或回應中。
